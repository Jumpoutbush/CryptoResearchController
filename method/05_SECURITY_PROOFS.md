# 05. 密码学安全模型与归约门禁

## 必须明确的前提

- 安全参数、算法族、威胁模型、网络/认证信道、静态或适应性腐化、腐化门槛和被动/恶意行为。
- 理想功能：输入、输出、允许的泄漏、延迟、掉线、选择性中止、可识别中止、公平性与安全组合环境。
- 敌手可以获得哪些局部份额、中间态、拒绝位、历史轮次输出、公开验证结果和失败反馈。

## 安全定理与证明

写出精确目标游戏或理想/现实不可区分定义；给出量化参数及条件。为每个混合实验列清事件、概率损失、归约者的运行成本，论证从实际协议到理想功能的每一跳。

安全证明要覆盖真实关键路径：承诺/认证一致性、抽取、份额正确性、动态集合分叉、跨轮相关性、模拟器如何产生输出，什么时候可以终止或泄漏。

对于格签名：无伪造、陷门/密钥分布、采样统计距离、签名拒绝、密钥刷新组合、共享采样泄漏和实现侧信道分别核查，不能由单方签名安全性自动推导恶意门限安全性。

对于安全聚合：定义跨轮隐私要保护的可观察量和可区分历史，明确独立动态权重是否与原强分组隐私冲突；给出可攻击的历史矩阵/动态授权或输出随机化模型。

## 静态与计算证据

Tamarin、EasyCrypt、Lean、Z3、模型检查器都只能在自身模型和已实现证明范围内提供证据。引用工具结论必须包含源文件、具体命题、构建命令、工具版本、退出码和输出日志。形式化证明覆盖不足的部分保持 OPEN。

“协议可运行”“经过若干测试”“模型自审通过”均不构成密码学安全证明。威胁模型不匹配时不能直接拿基线安全主张作比较。
