# 03. 先证伪：代数、密码学与协议敌手

为每个候选设置至少两类独立攻击角度：数学反例和研究意义反例。不可证明时先构造能直接否决本路线的最小实例。

## 数学 / 格构造

- 用精确整数/有理数枚举最小非平凡维度、极端系数、奇偶条件、非单位理想、同余到整数回升、近似舍入误差、不可逆元以及短性保持失败。
- 检查维数或通信下界是否被简单重参数化掩盖；独立计费隐藏变量、位宽与整数取商。
- 若依赖 Gram–Schmidt、频域、投影或采样，查清代数身份与数值误差是否被正确合并，是否存在统计偏差/侧信道。
- 从证明的**最弱环节**尝试构造具体满足前提但违反结论的实例。有限样例通过只能记 `COMPUTATION_CHECKED`。

## 密码协议 / 多方计算

- 明确恶意客户端、恶意聚合器、跨轮合谋、早退掉线、重放、承诺分叉、伪造份额、选择性中止、拒绝位泄露和输出集合变动。
- 尝试构造区分者、模拟器不可能兼容的视图、重复查询恢复攻击、同一统计量在动态集合下不一致的攻击。
- 检查安全定义是否隐含受信第三方，预处理是否把计算成本或信任转移到未计费方。

## 路线淘汰规范

`research/FAILED_PATHS.md` 每条至少给出：候选 ID；被否决命题；完整前提；最小见证/文献定理/成本表；可复现命令；失败分类（ALGEBRA / SECURITY / NOVELTY / LOWER_BOUND / COST / TOOL_LIMITATION）；能否通过新的引理挽救。不可重复进入同一个已否决路线，除非提出可精确证伪的新假设。

已证伪结论与“当前工具能力不足”必须分开。后者保留 OPEN，不能冒充不可能性定理。
