# 统一自动科研框架设计

## 一、整合结果

CryptoResearchController 作为底座，`projects/secagg-research` 和 `projects/falcon-dkg` 作为同一仓库中的研究项目。所有路径从入口脚本位置计算；搬到 D 盘或其他目录后仍能调用。项目以 PROJECT.json 中的稳定编号识别，预算和覆盖参数不依赖绝对路径哈希。

| 层级 | 文件或目录 | 职责 |
| --- | --- | --- |
| 用户入口 | research.py、research.cmd、research.ps1 | 选项目、运行、查询、想法、材料与模板 |
| 路线调度 | runner.py、route_budget.py | 预算、停滞、复评、同目标转向和验收 |
| 独立监督 | supervision.py、config/supervision_policy.json | 每三轮及预算节点审查、裁决与版本化指南、独立消耗及事务回滚 |
| 长期科研知识 | engine/knowledge_graph.py、engine/claim_graph.py | 共用主张图，关联文献、证据、失败路线与证明义务，版本化来源及传播失效 |
| 单轮执行 | runner_core.py | 注入方法、模型调用、输出检查、失败恢复 |
| 共用方法 | method、profiles | 查新、证伪、构造、证明、成本、复现、写作和审查 |
| 全局参数 | config/defaults.json、route_policy.json | 模型、超时、检索及预算默认值 |
| 项目参数 | config/projects/项目编号.json | 所选项目的例外参数 |
| 项目研究 | projects/项目编号 | 用户目标、个性材料、状态和科学证据 |
| 通用模板 | templates/project | 可复制的目录、台账和执行契约 |
| 本地运行 | logs、locks、state | 日志、互斥、预算账本、失败隔离 |

## 二、完整研究闭环

项目接入、材料登记 → 原文查新与最相近定理核验 → 最小反例与结构障碍 → 构造及正确性 → 安全与端到端成本 → 必要实验 → 论文主张与证据映射 → 独立审查。出现覆盖性论文、反例或前提改变时，返回最早失效的门禁。研究阶段是当前焦点，不能据此推断前面的门禁已经通过。

执行上，每轮依次读取目标、项目专用配置、想法与最新状态，刷新一批检索词并处理本地论文，再开展一个具体任务。报告、状态、受保护输入、证据链接和项目注册检查全部满足接口后才接收工作；随后写回预算与路线裁决，并在同一仓库保存局部检查点。接口验收与科学结论验证分别登记。

v3.3 在已验收工作和预算复评节点增加独立监督。监督进程只能读取，控制器保存并核对结构化提案后持锁提交允许管理区及审计文件。下一轮加载对应版本的短期指南；目标、安全定义、证明义务及原有路线裁决保持约束力。监督状态、重试与时长记在独立账本，成功、失败及回滚均保留来源。参见 [监督手册](SUPERVISION.md) 与 [v3.3 发布范围](RELEASE_V3.3.md)。

v3.4 在原 `research/discovery/CLAIM_GRAPH.json` 增加长期知识记录，不另建主张真源或复制证明审查状态。论文、外部定理、证据、失败路线和证明义务通过类型与依赖连接到现有主张；来源文件绑定摘要，依赖绑定版本。来源变化、上游修订或撤回会传到下游；已登记的明确失效和版本修订不能通过换回旧文件绕过重绑。原科学文件仍为原文依据；查询与提示词中的摘要只帮助定位，不能替代证明或原文核验。参见 [v3.4 使用说明](RESEARCH_KNOWLEDGE_V3.4.md)。

科研验收和尝试最终登记后，控制器持锁刷新知识索引，再判断独立监督触发。刷新失败保留已验收结果与消耗，在运行状态中登记 `knowledge_index`，以 `KNOWLEDGE_INDEX_FAILED` 停止后续监督；不会倒退科研账本。科研提示词与监督请求注入只读、有长度上限的知识上下文。追溯同时展示当前状态和推导所绑定的历史版本，缺失历史绑定明确保留，不替换为最新版本。

## 三、此次补齐的缺口

| 原始问题 | 修改 |
| --- | --- |
| C 盘控制器和 D 盘项目路径混用 | 根目录相对路径、统一运行目录 |
| 项目各自初始化 Git，底座不能对父仓库提交 | 一个根仓库、限定所选项目的检查点 |
| 参数名称冲突、旧 runner 多层备份 | 保留活跃调度链，统一 no-fetch 接口并删除失效副本 |
| 模型配置复制到项目 | 底座默认、中央项目覆盖、单次命令覆盖 |
| 预算依赖绝对目录且 dry-run 会写账本 | 稳定项目编号，查询和试运行保持只读 |
| 失败调用可能留下半更新状态 | 隔离失败材料，恢复已接收项目文件 |
| 核心执行提前提交，路线裁决在提交后变化 | 完成调度验收与路线处理后再保存检查点 |
| 研究项目结构和门禁存在缺口 | 修复 Falcon 检索文件、合并 SecAgg 有效研究提案 |
| 单轮未自动运行已有代数和结构检查 | 注册项目检查自动参与验收，失败时隔离并恢复 |
| 无想法登记与模板入口 | 稳定想法编号、更新记录、明确选中、新项目生成 |
| 检索词超过十条后长期不查询 | 分批轮转、保存检索覆盖与累计文献目录 |
| 历史实验依赖已删除样本及绝对路径 | 复制到独立复现目录并重建样本别名 |

## 四、扩展边界

新项目继承共用方法与目录；用户提供个性化目标、参数、安全定义和原始论文即可。模板生成的检索词只是初始检索入口，首次研究继续细化近邻检索和基线。新增领域配置时在 profiles 写方法文件并在 config/profiles.json 注册。项目科学台账可以保留领域特有结构；机器调度只依赖公共 STATE、GATES、单轮报告与路线信号，不强制将 Falcon 与 SecAgg 的所有主张账本改成同一格式。

科研新颖性和定理闭合仍需要原文和证据核验；本包完成了自动流程与可复现接口，保留两个项目尚未完成研究的真实状态。
