# v3.3 · 开发轮次 R01：监督事件契约与只读快照

> **执行状态：待开发（计划文件）**。本文是交给 Codex 的实施规格，并非已完成的功能说明。
> **基准：** `Jumpoutbush/CryptoResearchController@67618536ecd172b2fad24843daf291489e226c2e`；执行前以本机较新、已提交的源代码为准。
> **轮次类型：** 软件开发轮次；不得消耗任何个人科研项目的研究预算。

## 1. 本轮唯一目标

定义所有项目共用的监督事件、安全快照和配置格式。只实现确定性的本地逻辑，不调用模型，也不改变当前 `run/watch` 流程。

**现有基础：** `route_budget.load_ledger()` 已提供 `epoch`、`effective_rounds`、`last_processed_run`；`research_focus.make_focus()` 给出目标锚点；`runner_core.PROTECTED` 已保护项目指令。

**进入条件：** 基准回归测试通过；当前开发分支没有科研代理正在同时写入目标项目。

## 2. 设计裁决与数据流

### 1.1 快照只提取真正需要的证据

从单一项目的真实路径抽取：GOAL、已有 AGENTS、continue、STATE、`CLAIM_GRAPH.json` 的验证状态、最近 3 份已接受报告、路线账本摘要、选中想法、相关定理与近邻论文技术审查。每个源文件记录原相对路径、大小、SHA-256、是否摘要截断及验证等级。单次总文本大小先限定为 256 KiB；超限必须显式报告省略策略和遗漏文件，不能制造完整阅读的假象。

### 1.2 事件状态机

`QUEUED → RUNNING → PROPOSED → APPLIED`；失败分支 `FAILED/REJECTED/CONFLICT`。状态均持久化；任何状态转换必须保留来源触发轮次与目标绑定。事件不能直接要求某条主张从 `CANDIDATE` 变为 `INDEPENDENTLY_REVIEWED`。

### 1.3 来源级别

`USER_FROZEN`、`INDEPENDENTLY_REVIEWED`、`TOOL_CHECKED_AUDIT_PENDING`、`MODEL_CANDIDATE`、`UNVERIFIED`。无对应证明或审核回执时不能自称更高级别。

## 3. 修改范围（新增文件均为规划路径）

- 新建 `supervision/contracts.py`：事件和监督输出的 Python 类型/验证器。
- 新建 `supervision/snapshot.py`：只读信息提取器与摘要 manifest。
- 新建 `config/supervision_defaults.json`：`enabled=false`、`periodic_accepted_rounds=3`、`calls_per_event=1`、`max_snapshot_bytes=262144`、`max_guide_bytes=12288`、`model_tier=critical`。
- 新建 `tests/test_supervision_contract.py` 与模拟项目夹具；必要时在 `docs/` 增加模式说明。

## 4. Codex 必须完成的实现步骤

1. 对照 `configuration.settings_for` 和 `route_budget.load_ledger` 提取**只读**项目绑定；不得在预览过程中触发路由账本创建或写入。
2. 定义 `SupervisionEvent` 校验：稳定项目 ID、真实 run ID、真实 epoch、触发类型、目标哈希及版本、创建时间、输入 manifest。
3. 设计受限 JSON Schema，使用 `additionalProperties=false`；监督建议必须包含引用过的证据路径和判定依据。
4. 实现文件枚举白名单；拒绝符号链接、路径穿越、跨项目文件、过大的文献全文和包含密钥的运行环境文件。
5. 快照按确定顺序排序并哈希；相同输入再次提取，清单摘要相同。
6. 在自定义临时项目上运行读取器，验证不会新增/改变任何文件。

## 5. 输入、输出与接口约定

建议 `supervision/snapshot.py` 提供 `build_snapshot(project, *, last_n=3) -> Snapshot`，`contracts.py` 提供 `validate_event`、`validate_proposal`。名称如调整必须保留等价的稳定测试接口。

```json
{
  "schema_version": 1,
  "event_id": "通过规范序列化计算的真实 SHA-256",
  "project_id": "example-project",
  "trigger": "PERIODIC",
  "trigger_run_id": "已接受的真实 run ID",
  "route_epoch": 1,
  "goal_anchor_id": "冻结主线锚点",
  "status": "QUEUED",
  "source_manifest": [
    {"path": "GOAL.md", "sha256": "真实文件摘要", "trust": "USER_FROZEN"}
  ]
}
```

数据中的说明文字为字段示例，不得伪装成实际生产记录。

## 6. 必做的离线自动测试

- 同一项目同一轮次重复采样，得到相同的规范 manifest 摘要。
- 路径为 `../other-project/GOAL.md`、符号链接或绝对路径时拒绝。
- 缺少 `reports/LATEST.md` 时降级记录缺失，不能伪造最新报告。
- 旧 `CLAIM_GRAPH.json` 不存在时标记空索引、保持状态，不创建虚假主张。
- 文件超限明确显示 `truncated=true` 与省略字节数；GOAL 不能被截断后当作完整目标使用。
- 运行前后比较 fixture 全目录 SHA 集合，确认只读。

## 7. 本轮验收标准

- JSON Schema 和 Python 验证器拒绝非法输入。
- 快照中可逐条追溯所有来源文件哈希和验证级别。
- 不调用 Codex、不更改个人科研项目、不建立新的路线预算。
- 全量既有测试通过。

## 8. 停止、回滚及禁止事项

若冻结目标无法完整读取、项目 ID 与 manifest 不一致或路径验证失败，应直接拒绝构造快照；不得自动回退到未绑定的自由文本监督。

## 9. Codex 交付回执

- 填写修改文件列表、设计偏差及理由、`git diff --stat`。
- 提供专项测试与全套回归测试的真实命令、退出码、通过/失败数量。
- 输出一项**独立可复核**的正常路径证据和一项故障注入证据（测试文件/夹具/日志均可）。
- 报告是否改变既有科研项目的 `GOAL.md`、`STATE.json`、预算账本、门禁或任何证明结论；正常答案必须为“均未改变”。
- 使用英文、范围明确的 Git 提交说明；用户未授权时不要推送远端。

# v3.3 · 开发轮次 R02：监督触发器、独立预算与去重

> **执行状态：待开发（计划文件）**。本文是交给 Codex 的实施规格，并非已完成的功能说明。
> **基准：** `Jumpoutbush/CryptoResearchController@67618536ecd172b2fad24843daf291489e226c2e`；执行前以本机较新、已提交的源代码为准。
> **轮次类型：** 软件开发轮次；不得消耗任何个人科研项目的研究预算。

## 1. 本轮唯一目标

在已验收研究轮次之后产生持久化监督事件，实现每三轮触发、路线复评优先、独立调用账本，不调用真实监督模型。

**现有基础：** `runner.py.advance_one` 已区分 `COUNTED_RESEARCH_ROUND` 与 `ROUTE_REVIEW`；`needs_review` 决定原预算复评；`research.py.watch` 遵循 `last_run`。

**进入条件：** R01 契约和快照生成测试通过。

## 2. 设计裁决与数据流

### 2.1 触发优先级（固定）

- 已验收研究轮次且 `effective_rounds` 到达 3 的整数倍：周期监督。
- 该轮同时触发 `review_pending`：只记录 `DEFERRED_TO_ROUTE_REVIEW`，等内置 `--route-review` 验收后，将两项原因合并为**一次** `POST_ROUTE_REVIEW` 事件。
- 若人工主动请求监督，事件类型为 `MANUAL`；不得突破 STOP、活动尝试或不完整事务的限制。
- 失败轮、缺失 `ROUND_REVIEW`、独立监督自己的一轮、dry-run 均不计入 `effective_rounds`。

### 2.2 可靠队列

主键：项目 ID + route epoch + 触发源 run ID + 已规范化触发原因。事件写入原子文件，`event_id` 为哈希；按事件 ID 去重。`QUEUED` 不是已付费，执行前先预留 `CALL_RESERVED`，中断也保留预算消费记录。

## 3. 修改范围（新增文件均为规划路径）

- 新建 `supervision/scheduler.py`：`record_postaccept`, `pending`, `deduplicate`, `claim_event`。
- 新建 `supervision/ledger.py`：`state/supervision/<id>/events.jsonl`、不可变事件文件和调用记账。
- 在 `runner.py` **研究提交成功并事务结束** 的安全边界接入事件写入；避免监督崩溃使已接受科研回滚。
- 在 `research.py` 添加只读 `supervise status <项目>` 与 `supervise pending [项目] --dry-run`（若解析器已有同名接口，先合并）。
- 新建 `tests/test_supervision_triggers.py`。

## 4. Codex 必须完成的实现步骤

1. 用最少代码复用 `epoch['effective_rounds']`，不要新增 second_effective_rounds 字段。
2. 记录触发时冻结 `goal_sha256`、`anchor_id`、`selected_idea`、`route_epoch` 和源 run ID。
3. 原内置路线复评未完成时不允许监督修改指南；仅落盘“复评后再审”的持久事件。
4. 事件采用追加式操作日志；预留监督调用次数独立于研究预算和固定问题预算。
5. 确定性的离线调度支持模拟当前状态和时钟；重启后从队列恢复。
6. 测试 `run`、`watch` 与直接 `runner.py` 在同一个接入点产生相同事件，不另写一套 watch 计数。

## 5. 输入、输出与接口约定

新增 CLI 仅为计划，实施并通过解析测试后才对外发布：

```powershell
.\research.cmd supervise status secagg-research
.\research.cmd supervise pending --dry-run
```

`--dry-run` 读取结果但不得落盘新的事件、账本或临时配置。


## 6. 必做的离线自动测试

- 计数序列 `1,2,3,4,5,6` 只在第 3、6 个已接受轮产生周期事件。
- 相同 run ID 重放三次仍只有一个事件，且模型调用预算未消耗。
- 第 3 轮恰逢预算复评时，复评前无自动应用，复评后最多一个合并事件。
- 有活动 `attempt`、显式 `STOP_REQUESTED`、`NEEDS_INPUT` 的场景正确区分“允许只读建议”和“不允许改路线”。
- 并发模拟两个进程领取相同事件，只允许一方获得领取权。
- 模拟 Windows 锁占用与重启，待办队列不丢失。

## 7. 本轮验收标准

- 三轮触发、去重、复评优先三个性质均由测试证明。
- 成功的旧研究回执与路线使用量不变。
- 新旧 `research.cmd run/watch` 调用契约完全兼容。

## 8. 停止、回滚及禁止事项

任何情况下不得为了完成监督触发而自动运行 `refocus` 或增补研究预算。发生锁冲突只保留事件待办，并记录恢复原因，不启动第二个科研进程。

## 9. Codex 交付回执

- 填写修改文件列表、设计偏差及理由、`git diff --stat`。
- 提供专项测试与全套回归测试的真实命令、退出码、通过/失败数量。
- 输出一项**独立可复核**的正常路径证据和一项故障注入证据（测试文件/夹具/日志均可）。
- 报告是否改变既有科研项目的 `GOAL.md`、`STATE.json`、预算账本、门禁或任何证明结论；正常答案必须为“均未改变”。
- 使用英文、范围明确的 Git 提交说明；用户未授权时不要推送远端。

# v3.3 · 开发轮次 R03：独立 Codex 监督执行与结构化裁决

> **执行状态：待开发（计划文件）**。本文是交给 Codex 的实施规格，并非已完成的功能说明。
> **基准：** `Jumpoutbush/CryptoResearchController@67618536ecd172b2fad24843daf291489e226c2e`；执行前以本机较新、已提交的源代码为准。
> **轮次类型：** 软件开发轮次；不得消耗任何个人科研项目的研究预算。

## 1. 本轮唯一目标

实现真正独立的一次监督调用，模型只看到选定项目的只读资料，并只能返回经过 schema 限制的建议 JSON。

**现有基础：** `runner_core.codex_run` 已提供研究执行器；监督任务必须另建执行身份与日志，不共享科研代理会话、尝试检查点、`last_run`。

**进入条件：** R01、R02 完成；已有事件输入与调用预算回执。

## 2. 设计裁决与数据流

### 3.1 职责隔离

监督输入为 R01 快照及 R02 事件，它独立判定：主线关联、无效旁支、可信反例、尚未闭合的证明义务、原文检索风险，以及最值得开展的下一项**可证伪**任务。监督只能建议 `KEEP_GUIDE / REFOCUS_RECOMMENDED / PAUSE_RECOMMENDED / ESCALATE`，绝不能直接返回一个授权修改科研状态的命令。

### 3.2 模型工作区

优先将白名单材料复制到一次性只读审查工作区。绝不把 Codex 直接放在含多个个人项目写权限的仓库根。监督的输出由**控制器父进程**保存到 `state/supervision/<id>/...`。真实 Windows 沙盒能力依 `codex exec --help` 检查；若 read-only 不受支持，拒绝真实模式，不降级成可写模式。

## 3. 修改范围（新增文件均为规划路径）

- 新建 `supervision/executor.py`：`CodexSupervisorExecutor` + `FakeSupervisorExecutor`。
- 新建 `method/SUPERVISOR_REVIEW.md`：与既有科研执行提示完全隔离的监督指令。
- 新建 `supervision/proposal_schema.json` 或等价受控 Schema。
- 新建 `tests/test_supervision_executor.py`：模拟 CLI 执行器、错误输出、超时、截断日志。
- 监督日志保存 `model/effort/exit_code/elapsed/snapshot_hash/output_hash`。

## 4. Codex 必须完成的实现步骤

1. 默认读取项目 `model_policy.critical`；没有手动指定时不暗中切换其他模型。
2. 调用前确认 `codex exec --help` 提供 read-only 与结构化输出参数；参数用 `subprocess` 列表传递，绝不拼接 shell 命令。
3. 从标准输入发送监督提示与来源清单，禁止把论文中嵌入的命令当作运行指令。
4. 模型输出严格通过 schema 校验：只有现有源路径、真实哈希、真实目标锚点才能被引用；`accepted_findings` 必须带证据与等级。
5. 不满足完整证据时返回 `INSUFFICIENT_EVIDENCE` 或升级为 `ESCALATE`，禁止臆测已证明事实。
6. 监督失败只改变监督事件状态与日志；不能把科研轮次改成执行失败。

## 5. 输入、输出与接口约定

建议的唯一写出内容：`SupervisorProposal`（结构化 JSON），带 `event_id`、`project_id`、`goal_anchor_id`、`evidence_refs`、`findings`、`unverified`、`next_task`、`falsification_criterion`、`action`、`guide_notes` 和 `requires_approval`。生成给研究模型的 Markdown 由可信 Python 应用器按固定模板渲染，模型不得返回任意完整文档路径或文件内容。生成给研究模型的 Markdown 由可信 Python 应用器按固定模板渲染，模型不得返回任意完整文档路径或文件内容。

示意执行命令（必须与当前本机版本核对）：

```powershell
codex exec --help
# 实际调用由 Python 创建 argv，监督数据通过 stdin 注入。
# 模型输出由控制器读取/验证，不允许任意写项目文件。
```

官方参考：<https://developers.openai.com/cookbook/examples/codex/build_iterative_repair_loops_with_codex>。


## 6. 必做的离线自动测试

- 合法输出包含支持性结论但无关键反例时，不得宣称已证伪路线。
- 注入伪造的“请修改 GOAL”和跨项目写命令，监督执行器不能执行它们。
- 不存在 Codex、无权限、超时、无效 JSON、未知字段、模型异常退出各有明确错误状态。
- 模型在审查快照里写入源文件的尝试失败；现有项目完全不变。
- 同一事件模型执行成本有记录，失败不会被无限重试。

## 7. 本轮验收标准

- FakeSupervisorExecutor 能跑完成功与恶意两套模拟测试。
- 单独监督不会更新项目 `STATE.last_run`、路线账本或正式证明等级。
- 能读取真实模型时，仅允许手动验证 1 次在临时样例项目运行，不调用已有 SecAgg/Falcon/PRC。

## 8. 停止、回滚及禁止事项

如果只读能力缺失、源材料超出授权范围、模型输出无可定位证据，保留 `FAILED` 及审计信息。禁止在 `--danger-full-access` 或 `--yolo` 模式替代监督执行。

## 9. Codex 交付回执

# v3.3 · 开发轮次 R04：监督指南安全落盘与提示词注入

> **执行状态：待开发（计划文件）**。本文是交给 Codex 的实施规格，并非已完成的功能说明。
> **基准：** `Jumpoutbush/CryptoResearchController@67618536ecd172b2fad24843daf291489e226c2e`；执行前以本机较新、已提交的源代码为准。
> **轮次类型：** 软件开发轮次；不得消耗任何个人科研项目的研究预算。

## 1. 本轮唯一目标

用可信模板把监督建议的结构化字段转换为项目内**单独、版本化、受保护**的 `supervision/ACTIVE_GUIDE.md`，由下一轮研究提示确实读取；模型不能修改源目标、研究状态和科研门禁。

**现有基础：** 既有 `AGENTS.md` 和 `prompts/continue.md` 已被 `runner_core.PROTECTED` 保护；`build_prompt` 已按固定顺序读取它们。

## 2. 设计裁决与数据流

### 4.1 为什么采用独立文件

从源文件中抽取受控指南会冲突于旧版受保护输入；新增 `supervision/ACTIVE_GUIDE.md`（只有可信控制器可写）更易审计。生成指南区分：核心义务、待证事项、下一步可证伪任务、输入证据及禁止误判范围。

### 4.2 应用必须是事务

校验结构化输出 → 可信模板渲染 Markdown → 核对 `goal_anchor_id` 与源码 SHA → 核对 `old_guide_sha256`（无文件时固定空版本）→ 生成 diff → 保留旧内容 → 临时文件写入并 fsync → 原子替换 → 回执落盘。崩溃时根据新旧 SHA 决定恢复或补写回执，不能对同一事件再合成第二个版本。

指南注入必须在科研模型读取 `AGENTS`/continue 之后，并重申不能推翻 GOAL 与固定问题。

## 3. 修改范围（新增文件均为规划路径）

- 新建 `supervision/guide.py`：validate, preview_diff, apply, rollback。
- 在 `runner_core.build_prompt` 增加显式读取 `supervision/ACTIVE_GUIDE.md`，并添加不可覆盖的提示词优先级说明。
- 在 `runner_core.PROTECTED`/`PROTECTED_DIRS` 中将 `supervision` 标记为科研模型只读。
- 在 `templates/project/supervision/README.md` 中描述生成文件的来源、加载顺序、恢复方法。
- 新建 `tests/test_supervision_guide.py`。

## 4. Codex 必须完成的实现步骤

1. 旧项目未含 `supervision` 目录时照常启动；监督启用时由可信控制器按需建立。
2. 限制指南最多 12 KiB，章节标题由可信模板生成；模型只提交有证据的任务和判据字段。凡要求更改预算、修改目标或认可证明的字段，均拒绝自动应用。
3. 实施前重读目标 SHA、route epoch、选中想法和最新 accepted_run_id，任一变化则将提案变 `REJECTED_STALE`。
4. 任何自动变更只涉及 `supervision/ACTIVE_GUIDE.md`；改变 `AGENTS.md` 的长期策略需另设人工批准流程且不纳入自动写入。
5. 保留旧版内容和 SHA 的独立历史，不允许拿 Git 恢复被忽略的个人项目文件。
6. 提供只读预览、应用、回滚三个入口，由现有注册命令解析器暴露。

## 5. 输入、输出与接口约定

示例受控指南的内容结构：

```markdown
## 下一项可证伪任务

列出可核对输出和反例。

## 不应重复的旁支
引用已归档失败路线，不允许假定已证。
```

拟增接口：`research.cmd supervise apply <项目> --event <ID>`、`research.cmd supervise rollback <项目> --event <ID>`；若自动应用模式启用，仍执行同一校验器。


## 6. 必做的离线自动测试
