# 八、升级夹具、迁移验证与失败恢复演练

## 8.1 不接触真实个人项目的模拟仓库

建议在测试临时目录按本机模板创建 `projects/example-a` 和 `projects/example-b`，每个包含 GOAL、STATE、实际可执行 `scripts/check_project.py`、真实匹配的 `research/ROUND_REVIEW.json`、固定测试论文与模拟主张。必须使用既有 `research.py` 和 `runner.py` 的合法路径创建**已验收**测试回执，不允许直接伪造“验证通过”的科学结论。

- **项目 A：**三次可接受轮次，第三轮触发独立监督，下一轮确实注入新指南。
- **项目 B：**第二轮报告不满足回执，项目回滚且预算不前进；随后人工模拟 STOP，监督不能恢复。
- **项目 C（可选）：**三个候选 C1/C2/C3，C1 存在可复核反例，C2 已被近邻论文覆盖，C3 仍为待审。

## 8.2 安全迁移基线

迁移前保存下列 SHA-256 清单：

```text
projects/*/GOAL.md
projects/*/inputs/**
projects/*/research/STATE.json
projects/*/research/GATES.json
projects/*/research/PROOF_OBLIGATIONS.json
projects/*/research/discovery/CLAIM_GRAPH.json
state/routes/*.json
state/discovery/*.json
```

迁移必须在用户明确授权的静止时刻执行。首轮 v3.3 安装不应修改上述文件；新增生成指南只在单项目显式启用后触发。`supervise disable` 保留指南历史并关闭后续自动调用，不能把旧版本 AGENTS 内容覆盖为模板。

## 8.3 恢复动作与预期结果

| 场景 | 故障注入 | 必须保留 | 恢复动作 |
| --- | --- | --- | --- |
| 监督中断 | 模拟模型调用突然退出 | 原 accepted run、原指南 | 记录失败，手动恢复或受限重试 |
| 同一事件重复调用 | 再次消费相同 event ID | 只收费一次、只应用一次 | 返回已有回执 |
| 指南 CAS 冲突 | 在准备阶段外部改指南 | 用户新增内容及历史 | 仅保留待审提案、提示人工差异核查 |
| 上游证据被删 | 修改 PAPER/CLAIM 源文件 | 原历史、不乱改审查状态 | 标记索引失效、等待证据或再审 |
| 预算耗尽 | 触发内置路线复评 | 已用预算与路线历史 | 先正式复评，再监督新任务 |
| 固定问题活动中 | 监督建议换题 | 活动 attempt 及其检查点 | 记录建议，等待正规 close/start |
| 控制器升级失败 | 核验失败的补丁 | 原配置及个人项目 | Git 回退控制器源码；个人文件用独立快照恢复 |
| 基准泄露 | 模型能读取隐藏 oracle | 所有原始任务与回放日志 | 标记评估无效，修复隔离，建立新题目版本 |

## 8.4 重要的开发边界

个人 `projects/` 可能被 Git 忽略。**Git 提交仅能保证追踪文件回滚**，所以对科研项目历史的回滚必须使用独立文件快照、SHA-256、原子写入和追加事件日志。禁止 Git 命令清理或还原未被跟踪的研究证据。

## 8.5 发布审查材料

每个版本至少保留一个成功演示、一个故障注入演示、完整测试输出、原文件哈希、升级后哈希、变更提交以及可用的 rollback 命令。只有结构测试通过，不能证明密码学研究成果已获同行验证。
