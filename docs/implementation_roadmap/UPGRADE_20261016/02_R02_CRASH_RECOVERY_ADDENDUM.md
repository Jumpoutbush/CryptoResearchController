# R02 兼容补充：冻结输入、中断恢复与防重复调用

**适用：正在进行的 R02。** 不改变 R01 已提交的 schema、事件 ID、快照内容和事件主状态机；下列字段仅为语义参考，Codex 应先映射到本地已经实现的日志/账本接口。R02 仍然不执行真实付费模型。

## 一、必要的三种不同保证

1. **事件至多登记一次**：相同研究接受事件恢复多次，只产生一个稳定 `event_id`。
2. **本地监督记账至多一次**：相同 `event_id` 只有一个已提交消费记录；读取并恢复已存在的完成回执不会再次扣除监督预算。
3. **外部付费调用无法仅凭本地文件保证恰好一次**：子进程派发后主进程意外退出，可能无法判断模型是否真的收到请求或产生费用。在没有提供方幂等键/可靠回执时，必须标记 `UNKNOWN_EXTERNAL_OUTCOME`，阻止自动重复调用；不能宣称已避免所有实际重复计费。

第三项是科研成本真实边界，README、用户界面和测试报告必须如实区分。

## 二、恢复状态与权威来源

R01 既有 `QUEUED/RUNNING/PROPOSED/APPLIED/...` 状态保持不变。R02 可使用追加式**内部调用生命周期日志**（名称遵守已有实现）：

- `CLAIMED`：领取方持有排它租约；租约须含 `event_id`、所有者、进程识别、原始事件版本、领取时间和租约世代。
- `CALL_RESERVED`：在**唯一账本**中记录可恢复的预算预留，冻结输入哈希和模型路由。
- `CALL_DISPATCHED`：进程即将/已经进入外部请求；若此后缺少完成回执，结果视为未知。
- `CALL_COMPLETED`：原始外部结果摘要、日志与受限输出已持久化，可重复读取但绝不重复调用。
- `OUTCOME_UNKNOWN`：上层状态可维持 `RUNNING`/`NEEDS_REVIEW`，但内部禁止自动重派发。

不要通过在 `events.jsonl` 和另一份 `call_count.json` 中分别累计来形成两个真相源；若必须投影计数，只从事件生命周期日志归约，并在同一排它锁下提交。重启先从日志重建，不得依据缺失文件假设消费为零。

## 三、冻结输入丢失的强制停机

事件引用的 `GOAL`、`selected_idea`、主线锚点及 `source_manifest` 必须可从已冻结快照重现。输入快照缺失、内容哈希变化、存在符号链接/越界文件或必要来源被截断时：

- 写 `BLOCKED_MISSING_FROZEN_INPUT`（或现有等价错误状态）；原事件不得被重新绑定到新的 GOAL；不调用模型。
- 记录缺失/损坏的确切相对路径和预期哈希，但不要在日志中打印可能含私密内容的全文。
- 若尚未派发外部模型，可按**有证据的预留释放**流程归还预留；若曾派发，必须保留消费风险和事件审计记录。
- 恢复时由操作者确认从可靠快照恢复原字节；不能静默重新创建输入并视为旧事件。

## 四、中断矩阵（离线故障注入必须覆盖）

| 崩溃点 | 恢复动作 | 预算与安全判据 |
| --- | --- | --- |
| 已验收科研轮次、监督事件尚未登记 | 基于源 run_id 重放 postaccept 幂等登记 | 不新增科研轮；恰好一个监督事件 |
| 事件已持久化、尚未领取 | 从 `QUEUED` 恢复 | 无外部调用消费 |
| `CLAIMED` 后、预算预留前 | 失效租约后可重新领取 | 无预算消费 |
| `CALL_RESERVED` 后、确认从未派发 | 审计后恢复待办或释放预留 | 无重复预留；不能默默丢事件 |
| `CALL_DISPATCHED` 后、没有回执 | 阻塞自动重派发，标记未知结果 | 不重复本地记账；外部扣费未知 |
| `CALL_COMPLETED` 回执已落盘、外层状态未更新 | 重放回执校验、推进外层状态 | 不启动第二次 Codex |
| `PROPOSED` 后指南应用前 | 再检快照/GOAL/权限后应用 | 采用已签收提案，无额外模型消费 |
| 指南写临时文件后崩溃 | 比对 active 文件/指针哈希，完成或回滚原子替换 | 绝不出现半写指南 |
| 两个进程同时领取相同 `event_id` | 仅一个获得锁/有效租约；另一退出 | 最多一次正式派发 |
| 监督失败恰逢内置 `--route-review` | 延后该事件，复评完成后合并复查 | 科研路线账本权威不变 |

## 五、实现接口不变量

事件主键绑定 `project_id + route_epoch + accepted_run_id + normalized_reason`，归一化过程必须与已完成 R01 契约一致。建议内部以 `event_id + call_generation` 作为账本条目键；世代只用于安全恢复，不能为同一个事件免费产生第二次外部调用。

各步骤采用排他锁、持久化写入和必要的 fsync；Windows 上要演练原子替换失败、文件被占用、重启后文件句柄释放。禁止自动删除 `.lock` 来“修复卡住”；需要识别持有者/存活性并在证据充分时回收过期租约。

调用提供方前，必须在日志中冻结模型标识、推理强度和 CLI 参数，但**不要记录登录令牌**。重复启动时只允许读取旧调用回执；未知外部结果必须有操作者确认的专用恢复路径，默认失败关闭。

> 理论关键：除非提供方明确支持可验证的幂等执行，否则“不会重复扣费”只能承诺控制器本地不自动重复派发与不重复记账，不能承诺远端计费系统的实际账单恰好一次。
