# v4.0 R16 开源融合附录：有隐藏标准答案的密码学研究基准

> 这是原版 `versions/v4.0/R16_*.md` 的**补充实施规格**，原文仍是基础契约。现有代码优先，新增内容不得倒逼重做先前轮次。科学进展与开发提交分别验收。

## 一、本轮明确交付

建立至少六类标准化研究任务，把科学能力与系统正确性评估分开。

## 二、对应的公开实现 / 已有代码

已有 `tests/research_benchmark`；[ARA](https://github.com/ARA-Labs/Agent-Native-Research-Artifact) 的过程证据形式。外部仓库读取时核对当前许可证并固定 SHA；不得直接安装运行整个系统。

## 三、推荐修改位置（以本机已实现模块为准）

1. `evaluation/benchmarks/manifest.json`、独立判题器
2. `evaluation/validate_cases.py`、`tests/test_benchmark_cases.py`

## 四、本轮实现及技术取舍

1. 六类任务分别覆盖论文覆盖、数学反例、安全漏洞、开放障碍界定、研究漂移和状态恢复
2. 金标准优先采用确切来源/程序见证；开放问题只测界定和未知声明的准确性
3. 秘密评分 oracle 不注入研究代理上下文，模拟任务不含用户私有材料
4. 每个任务登记允许的工具、模型、时间、固定输入 SHA 和评分说明
5. 所有评分函数本身先用正负样例验证

## 五、必须增加的失败测试

1. 错误安全归约样本能触发明确拒绝
2. 隐藏反例未暴露在公开任务说明或代理快照中
3. 开放问题未得到证明不会自动给失败结论
4. 任务文本修改使旧结果过期

## 六、本轮退出条件

已有明确独立金标准的最小任务集可离线运行，能返回每项可审计评分回执。

**统一禁止项**：不能改写个人项目 `GOAL.md`、研究成果状态或独立审查回执；不能默许模型把候选变已证明；不得因添加新模块重置已有科研轮次预算。每轮记录外部源码的具体上游提交、许可证、参考函数/文件、替代原理及必要适配测试。

## 七、补充公开研究/验证基准

参考 `UPGRADE_20261016/12_PUBLIC_RESEARCH_EVIDENCE_REFERENCES.md`。OpenAI Math 的已发布数学工件、PaperBench 的独立复现评分和 Google Science One 的证据链审计只能在对应的权限与安全定义下复用；实现时记录核对的上游 SHA 和本地适配测试，禁止据此自动升级数学主张状态。
