# v3.3 R02 开源融合附录：中断恢复兼容验收

> 这是原版 `versions/v3.3/R02_*.md` 的**补充实施规格**，原文仍是基础契约。现有代码优先，新增内容不得倒逼重做先前轮次。科学进展与开发提交分别验收。

## 一、本轮明确交付

完成用户正在开发的冻结输入丢失、预留中断、回执中断恢复；不改变已提交模式。

## 二、对应的公开实现 / 已有代码

现有 R01/R02 实现和 `route_budget`，不引入新第三方运行时。外部仓库读取时核对当前许可证并固定 SHA；不得直接安装运行整个系统。

## 三、推荐修改位置（以本机已实现模块为准）

1. 只扩充 `tests/test_supervision_triggers.py` 或现有同功能测试
2. 必要时对 `supervision/ledger.py` 增加已有日志的归约读取器
3. 操作说明必须引用 `../02_R02_CRASH_RECOVERY_ADDENDUM.md`

## 四、本轮实现及技术取舍

1. 在不重写 schema 的条件下定位已提交事件状态、不可变快照和唯一消费凭证的实际字段
2. 把预留未派发、派发后未知、已有回执未更新这三类恢复分开处理
3. 已派发且无回执时不得自动重新调用 Codex；记录远端成本未知并要求人工审计
4. 对 `runner.py` 的 postaccept 和 route review 两种触发使用同一幂等入口

## 五、必须增加的失败测试

1. 同一源 run_id 连续恢复 3 次只登记一个事件
2. `CALL_COMPLETED` 已落盘但父进程退出，重启不消耗第二次监督调用
3. 冻结 GOAL 原字节丢失，系统停止而不会生成新的来源快照
4. 模拟锁竞争和 Windows 原子文件替换失败，不产生第二派发

## 六、本轮退出条件

R02 专项、真实控制器模拟验收和全套回归通过；记录本机测试退出码并保留现有提交历史。

**统一禁止项**：不能改写个人项目 `GOAL.md`、研究成果状态或独立审查回执；不能默许模型把候选变已证明；不得因添加新模块重置已有科研轮次预算。每轮记录外部源码的具体上游提交、许可证、参考函数/文件、替代原理及必要适配测试。
