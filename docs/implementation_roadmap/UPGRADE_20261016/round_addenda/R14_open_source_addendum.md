# v3.5 R14 开源融合附录：恶意安全与归约的语义审查

> 这是原版 `versions/v3.5/R14_*.md` 的**补充实施规格**，原文仍是基础契约。现有代码优先，新增内容不得倒逼重做先前轮次。科学进展与开发提交分别验收。

## 一、本轮明确交付

把安全游戏、腐化、拒绝泄漏、模拟器及组合安全分解为可核验义务与错误反例。

## 二、对应的公开实现 / 已有代码

本地 `research_quality`、`research/THREAT_MODEL.md`、`claim_graph`；参考 [ARA rigor-reviewer](https://github.com/ARA-Labs/Agent-Native-Research-Artifact) 的结构化问责思路。外部仓库读取时核对当前许可证并固定 SHA；不得直接安装运行整个系统。

## 三、推荐修改位置（以本机已实现模块为准）

1. `candidate_search/security_model.py`、`security_review.py`
2. 模板 `SECURITY_OBLIGATION_TEMPLATE.json`、`tests/test_security_review.py`

## 四、本轮实现及技术取舍

1. 安全义务卡固定敌手模型、腐化时机、输出/拒绝泄漏、设置、模拟器接口和归约损失
2. 检查模拟器是否要求理想功能未给的秘密信息或不存在的可编程性
3. 检查多轮协议的接受/拒绝位、分叉、动态掉线是否纳入所声明泄漏
4. 组件安全证明与端到端协议归约分开登记，不能自动复用
5. 审查失败可提出精确最小攻击执行轨迹；无反例时保持待证而非通过

## 五、必须增加的失败测试

1. 静态恶意安全被声称自适应安全时拒绝
2. 公开拒绝位造成可区分性且模拟器遗漏时触发失败
3. 复用原论文定理却删去前提时审查不通过
4. 跨轮合谋安全游戏要求未明时保留 NEEDS_INPUT

## 六、本轮退出条件

可准确指出最早缺失的安全游戏或归约义务，所有主张确认仍由独立审查流程完成。

**统一禁止项**：不能改写个人项目 `GOAL.md`、研究成果状态或独立审查回执；不能默许模型把候选变已证明；不得因添加新模块重置已有科研轮次预算。每轮记录外部源码的具体上游提交、许可证、参考函数/文件、替代原理及必要适配测试。
