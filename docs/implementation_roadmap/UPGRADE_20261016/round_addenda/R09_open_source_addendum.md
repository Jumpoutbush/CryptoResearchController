# v3.4 R09 开源融合附录：证据检索与上下文装配

> 这是原版 `versions/v3.4/R09_*.md` 的**补充实施规格**，原文仍是基础契约。现有代码优先，新增内容不得倒逼重做先前轮次。科学进展与开发提交分别验收。

## 一、本轮明确交付

以核心义务为中心检索最重要的原文和证据片段，在不丢失关键条件的前提下减少上下文和跑偏。

## 二、对应的公开实现 / 已有代码

[PaperQA2](https://github.com/Future-House/paper-qa)：查询迭代、片段重排、出处；现有 build_prompt 输入。外部仓库读取时核对当前许可证并固定 SHA；不得直接安装运行整个系统。

## 三、推荐修改位置（以本机已实现模块为准）

1. `knowledge/retrieval.py`、`knowledge/context_builder.py`
2. `tests/test_knowledge_retrieval.py`

## 四、本轮实现及技术取舍

1. 默认使用标准库关键词/索引；可选启用 PaperQA2 式语义重排，不设为控制器硬性依赖
2. 返回 source_id、版本、原文位置、核验等级及显式截断标记
3. 先保留冻结 GOAL/安全定义/活动义务，再按关联性选择其他证据
4. 把提取中有公式错误风险的片段标记 MATH_RENDER_UNCERTAIN
5. 缓存命中必须核对原始文件 SHA，索引失效则降级到确定性查找

## 五、必须增加的失败测试

1. 缺少外部 API/嵌入服务依然可检索
2. 同一原文不同版本不得跨版本拼接证明
3. 预算限制下不截断冻结目标后冒充完整
4. 私有 PDF 默认不会向第三方上传

## 六、本轮退出条件

查询返回明确来源和验证等级，模型提示词维持原安全约束与最大上下文预算。

**统一禁止项**：不能改写个人项目 `GOAL.md`、研究成果状态或独立审查回执；不能默许模型把候选变已证明；不得因添加新模块重置已有科研轮次预算。每轮记录外部源码的具体上游提交、许可证、参考函数/文件、替代原理及必要适配测试。
