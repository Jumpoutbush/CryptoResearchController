# v3.5 R15 开源融合附录：分支收束、失败保留与恢复

> 这是原版 `versions/v3.5/R15_*.md` 的**补充实施规格**，原文仍是基础契约。现有代码优先，新增内容不得倒逼重做先前轮次。科学进展与开发提交分别验收。

## 一、本轮明确交付

使候选淘汰、暂停或切换保留完整反例证据和成本历史，防止重复研究已知失败路径。

## 二、对应的公开实现 / 已有代码

[AIDE journal](https://github.com/WecoAI/aideml/blob/main/aide/journal.py) 与 [ARA trace](https://github.com/ARA-Labs/Agent-Native-Research-Artifact)：保留失败节点。外部仓库读取时核对当前许可证并固定 SHA；不得直接安装运行整个系统。

## 三、推荐修改位置（以本机已实现模块为准）

1. `candidate_search/resolution.py`、`candidate_search/history.py`
2. `tests/test_candidate_end_to_end.py`

## 四、本轮实现及技术取舍

1. RETIRE/REFUTE/COVER 的裁决按证据等级不同处理，模型建议不能直接给 REFUTED
2. 失败路线的核心假设和具体最小反例保留为可查链接
3. 新候选对旧候选做最小条件变更，登记何时可以重启该方向
4. 与旧 `refocus`/`attempt close` 协调，审查流程不能覆盖尚未核验的 checkpoint
5. 新阶段与旧阶段同一预算账本，同一研究目标锚点

## 五、必须增加的失败测试

1. 被否定的局部构造不能导致整个签名族自动停机
2. 恢复某旧分支仍继承其曾用预算
3. 重启被反例覆盖的路线必须有新假设与审查记录
4. 取消后保留所有数学失败证据

## 六、本轮退出条件

v3.5 闭环支持分支提案、证伪、归档、收束并回到主线，历史与成本可追溯。

**统一禁止项**：不能改写个人项目 `GOAL.md`、研究成果状态或独立审查回执；不能默许模型把候选变已证明；不得因添加新模块重置已有科研轮次预算。每轮记录外部源码的具体上游提交、许可证、参考函数/文件、替代原理及必要适配测试。
