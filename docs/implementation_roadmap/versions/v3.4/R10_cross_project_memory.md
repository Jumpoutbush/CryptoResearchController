## 1. 本轮唯一目标

允许跨项目发现可参考的数学障碍和文献，但任何结论进入另一个项目必须重新检查假设与安全模型；完成 v3.4 闭环回归。

**现有基础：** `PROJECT.json` 给出稳定项目 ID，现有科研项目具有不同 GOAL 和用户材料；现有主张图的 ID 只在项目内部唯一。

**进入条件：** R06—R09 完成并通过全部专项测试。

## 2. 设计裁决与数据流

### 10.1 复用边界

跨项目索引只允许检索显式授权的项目公开/可分享材料，默认仅含论文身份、经明确许可的理论结论摘要与失败路线标签。不同项目相同关键词不意味着相同困难问题；必须提供“适用模型、量词、假设、域、敌手”和目标项目的逐项映射。

**跨项目知识仅标记 `REFERENCE_ONLY`**；若想成为目标项目正式主张，必须通过已有 `claim import`、文献定理核查与独立审查。

### 10.2 隐私隔离

默认关闭跨项目读取；即使所有项目在同一个本地仓库，也不能因此把个人源码、私有论文 PDF 和日志自动分享给其他研究代理。

## 4. Codex 必须完成的实现步骤

1. 设计 `SharedReference` 包含 origin project、source hashes、公开许可、映射假设及目的项目。
2. 只有取得目标项目配置明确允许的读取才建立跨项目引用；拒绝路径穿越与 Git 忽略目录的默认分享。
3. 重名候选按项目、问题版本、定理上下文进行冲突标记。
4. 对目标项目的引用生成“可能相关”候选链接；不写 `CLAIM_GRAPH` 或修改 `verified_results`。
5. 运行 R06—R09 的删除重建、SHA 冲突、失效传播和上下文裁剪测试。
6. 用两个最小虚拟项目演示相同 NTRU 等式在不同参数/安全假设下不自动复用。

## 6. 必做的离线自动测试

- 未授权项目之间无法读取彼此私有材料。
- 同名术语、不同敌手模型的主张不自动归并。
- 直接删除知识索引后可从原始文件完整重建。
- 模拟一个原文源 SHA 改变导致跨项目引用失效，却不改变任何项目原主张等级。
- 关闭跨项目功能时，现有 SecAgg/Falcon/PRC 行为不变。

## 7. 本轮验收标准

- v3.4 T07—T09 全部通过，并提供至少一条完整可追溯的知识引用链。

- 生成知识图谱及摘要过程零付费、零网络请求（除显式原文获取任务）。
