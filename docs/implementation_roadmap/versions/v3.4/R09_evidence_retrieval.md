# v3.4 · 开发轮次 R09：可信分级检索与长期上下文压缩

> **执行状态：待开发（计划文件）**。本文是交给 Codex 的实施规格，并非已完成的功能说明。
> **基准：** `Jumpoutbush/CryptoResearchController@67618536ecd172b2fad24843daf291489e226c2e`；执行前以本机较新、已提交的源代码为准。
> **轮次类型：** 软件开发轮次；不得消耗任何个人科研项目的研究预算。

## 1. 本轮唯一目标

让科研和监督代理只看到最相关、可验证状态明确的证据子图，减少重复补证、错误结论复用与长上下文漂移。

**现有基础：** `runner_core.build_prompt()` 已注入核心目标与最新报告，但长报告会截断；现有 `knowledge`（R06—R08）能提供带身份与哈希的子图。

**进入条件：** R06—R08 的身份、来源和失效链测试通过。

## 2. 设计裁决与数据流

### 9.1 检索排序不等于科学真理

输入为冻结 `goal_anchor`、选中问题/义务 ID、当前任务与预算；优先取该义务的权威主张、必要依赖、反例、被覆盖的近邻文献和未解决缺口。排序只决定读什么，不改变证明等级。

推荐检索顺序：问题的必要依赖与反例 → 明确 CORE/DIRECT_DEPENDENCY 的已验收结果 → 原文定理证据 → 待审候选 → 普通背景。缺少必要证据时输出“缺失清单”，而不是填充虚假摘要。

### 9.2 上下文预算

建议单次核心摘要不超过 32 KiB；超额时按照依赖优先级裁剪，显式保留被截断列表、每份摘要源 SHA 与索引版本。

## 3. 修改范围（新增文件均为规划路径）

- 新建 `knowledge/retrieval.py`、`knowledge/context_builder.py`。
- 增加测试 `tests/test_knowledge_retrieval.py` 与固定排序夹具。
- 对 `runner_core.build_prompt` 增加**可开关**的知识子图上下文装配，不替换已有 GOAL、STATE 或报告契约。
- 监督 snapshot 可复用同一个可信检索器；先作为可选模式。

## 4. Codex 必须完成的实现步骤

1. 精确查询优先支持 `claim_id/problem_id/obligation_id`；自由文本仅辅助召回，不能自动合并不同定理。
2. 每个入选片段输出 `source_file + sha256 + claim_revision + verification_status`。
3. 排除已失效结论作为正面依据；可作为“历史失败路线”引用并明确失效条件。
4. 检索对输入状态和索引版本应确定性可重现；默认不引入外部向量服务。
5. 接入 `build_prompt` 时对照原始版本进行差异回归，保证上游目标/安全边界保持完整。
6. 设计 `knowledge context --task ... --dry-run` 的只读预览，列出选入和舍弃的证据。

## 5. 输入、输出与接口约定

建议的 `EvidenceContext`：

```json
{
  "goal_anchor_id": "真实锚点",
  "target_obligation": "O-001",
  "index_digest": "真实索引摘要",
  "selected": [{"node_id": "...", "evidence_sha256": "...", "trust": "..."}],
  "omitted": [{"node_id": "...", "reason": "budget"}],
  "missing_required": []
}
```


## 6. 必做的离线自动测试

- 固定相同查询和索引，排序与摘要字节级一致。
- 当历史最新报告大量描述无关引理时，核心义务相关反例排在前面。
- 上游失效主张不会被当成当前可用定理提供。
- 超过上下文预算时明确显示遗漏的证据和必要依赖。
- 关闭知识检索时提示词与 v3.3 版本无差异。
- 模型注入语句混在论文中，不被提升为 controller 指令。

## 7. 本轮验收标准

- 可以针对一个真实或模拟的复杂证明义务，输出完整的有来源上下文清单。
- 不自动重新认可审查状态，不改变研究任务及预算。
- 知识检索开关在不安装 SQLite 特性时可正常停用。

## 8. 停止、回滚及禁止事项

若来源索引有冲突或受影响节点状态未知，保持未确认并降低排序优先级；必要核心证据缺失时明确标注。
