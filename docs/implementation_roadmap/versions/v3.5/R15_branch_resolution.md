# v3.5 · 开发轮次 R15：候选树收束、分支归档、复评与回滚

> **轮次类型：** 软件开发轮次；不得消耗任何个人科研项目的研究预算。

## 1. 本轮唯一目标

实现候选研究树的可控切换、淘汰与复用闭环，在不丢失失败证据的情况下返回核心目标，完成 v3.5 端到端测试。

**现有基础：** `refocus` 能保留预算和历史；固定问题切换需 `attempt close`；`FAILED_PATHS.md` 记录失败路线，claim 图处理依赖失效。

**进入条件：** R11—R14 完成且模拟项目无需新建第二份研究控制器。

## 2. 设计裁决与数据流

### 15.1 裁决分层

候选状态可以根据有证据的结构审查转为 `REFUTED/COVERED/RETIRED/CONDITIONAL`；对 `COVERED/REFUTED` 需要定理级原文映射或可复核反例证书。一个候选被否决不代表其父问题或全部同族构造都不可能。

### 15.2 切换协议

完成当前尝试检查点 → 原 `attempt close` 保存历史 → 验证新问题版本和 GOAL 锚点 → 原 `problem import`（若尚未登记）→ 显式 `attempt start` → `run`。所有累计路线消耗依然来自老账本，保留历史输入哈希。

### 15.3 分支搜索和监督联动

监督可以推荐从已否决候选切换，但不能绕过正在进行的固定问题、route pending review、STOP 状态或用户冻结的科研目标。

## 3. 修改范围（新增文件均为规划路径）

- 新建 `candidate_search/resolution.py` 与 `candidate_search/history.py`。
- 新增 `candidate retire/compare/history` 等命令（确认契约后发布）。
- 添加 `tests/test_candidate_end_to_end.py`、断点恢复与预算逃逸模拟。
- 更新用户手册及候选模式与监督模式协同说明。

## 4. Codex 必须完成的实现步骤

1. 通过实际现有命令接口完成同一目标下候选 A→B 的受控切换，不能直接变更 `STATE.selected_idea` 来偷换目标。
2. 将候选 A 的否决依据及适用前提归档成可查询的知识图谱节点。
3. 对仍可能有用的独立引理标记 `DIRECT_DEPENDENCY` 或 `SUPPORT`，不得删去历史反例。
4. 将监督建议和候选切换方案分开存储，路线裁决仍经 `--route-review/refocus` 原逻辑。
5. 模拟切换前崩溃、关闭固定问题失败、证据被改等情况，确保不会出现两个 ACTIVE 分支。
6. 完成对旧 `run/watch/attempt/refocus/claim review` 的回归。

## 5. 输入、输出与接口约定

输出格式至少应展示：候选版本、结论适用范围、反例证据、被否决原因、已用科研轮数及仍未闭合的原证明义务。


## 6. 必做的离线自动测试

- 所有候选共用原 route budget；切换不能制造新预算纪元以规避历史消耗。
- 任何时刻至多一个活动固定问题尝试。
- 被覆盖候选具有真正经过核查的原文包含关系；无原文时停在条件性。
- 退役候选仍可查询原始证据与研究日志。
- 切换失败后旧 active 状态和研究历史一致，可人工恢复。

## 7. 本轮验收标准

- v3.5 T10—T11 通过。
- 有完整演示：A 查新→最小反例→否决并归档→B 启动，期间路线有效轮数连续。
- 候选调度禁用时，基准研究流程不变。

## 8. 停止、回滚及禁止事项

候选遍历不是自动发表系统。没有定理级新颖性与独立安全审查的候选只能作为待审方向。
