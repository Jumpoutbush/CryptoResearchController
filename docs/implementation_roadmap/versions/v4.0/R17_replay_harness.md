# v4.0 · 开发轮次 R17：固定输入、确定性离线科研回放

> **执行状态：待开发（计划文件）**。本文是交给 Codex 的实施规格，并非已完成的功能说明。
> **基准：** `Jumpoutbush/CryptoResearchController@67618536ecd172b2fad24843daf291489e226c2e`；执行前以本机较新、已提交的源代码为准。
> **轮次类型：** 软件开发轮次；不得消耗任何个人科研项目的研究预算。

## 1. 本轮唯一目标

建立不消耗付费模型调用的基准重放能力，对比单代理、控制器、控制器加监督、完整版本四种策略；支持故障注入和历史复现。

**现有基础：** `runner_core.ProjectTransaction`、现有测试假 Codex、`state/routes` 和 discovery 账本已提供可复现记录点；新增回放应只在隔离工作区模拟。

**进入条件：** R16 至少 6 个经过检查的可评分夹具与隔离规则。

## 2. 设计裁决与数据流

### 17.1 四条固定对照

A：单代理模拟；B：基线 v3.2 控制器；C：v3.3 监督启用；D：v3.4+v3.5 完整增强。对照使用相同公开任务、相同预先录制的代理输出或相同受控模型调用限制。模型版本、采样随机性和工具差异不能悄悄改变。

### 17.2 真实可重放性的边界

离线模拟可检验调度、权限、预算、证据回收与评价器，**不能证明真实语言模型能力提高**。真实模型比较必须另外安排统一预算、冻结题目、足够样本并记录误差区间。

## 3. 修改范围（新增文件均为规划路径）

- 新建 `evaluation/replay.py`、`evaluation/fake_codex.py`、`evaluation/isolation.py`。
- 新增 `research.cmd bench replay <case> --variant <A|B|C|D> --offline` 等入口，命令仅在实现后公布。
- 添加 `tests/test_benchmark_replay.py` 和中断/重试夹具。
- 结果写 `state/evaluation/runs/`，不写入个人科研项目。

## 4. Codex 必须完成的实现步骤

1. 每次回放从只读快照复制到临时沙盒，隔离 Git 工作树、环境凭据和隐藏金标准；实际核查操作系统级权限，而不能只依赖提示词。
2. 固定测试种子、输入排序、模型伪响应及文件内容；保存 fixture 的 SHA 和控制器源码提交哈希。
3. 执行流程包括触发、研究回执、证据验收、监督队列、知识图谱更新与候选状态，必要时用假执行器替换 Codex。
4. 输出事件追踪 `events.jsonl`，逐项标注科研调用、监督调用、工具核验与失败。
5. 对中断恢复采用真实日志+检查点，不在回放时修改原有历史科研记录。
6. 不允许回放读取私有 oracle 直到评价阶段，确保分离。

## 5. 输入、输出与接口约定

模拟 CLI：

```powershell
.\research.cmd bench replay BENCH-LIT-001 --variant B --offline
.\research.cmd bench replay BENCH-LIT-001 --variant D --offline
```

结果保留 `controller_commit, fixture_hashes, variant, trace_hash, cost_counts, evaluator_version`。


## 6. 必做的离线自动测试

- 同一版本、种子和输入重复运行的可判定事件轨迹哈希一致。
- 断电/半完成状态只回收当前回放，不影响其他任务。
- A/B/C/D 对照均使用同一 public task 和 oracle 评分规则。
- 实验模拟器没有任何付费请求、无网络下载、没有向本机科研目录写入。
- 科研与监督调用次数分别登记，失败调用计费情况清晰。

## 7. 本轮验收标准

- 可复现一个已知失败的科研漂移测试，以及监督介入后的行为改变。
- 证明的是**控制流程**在测试条件下可靠，不能宣称开放数学任务成功率改善。
- 有结构化轨迹和差异说明。
