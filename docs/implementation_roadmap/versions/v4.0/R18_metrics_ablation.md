> **轮次类型：** 软件开发轮次；不得消耗任何个人科研项目的研究预算。

## 1. 本轮唯一目标

提供可审计的实证指标，证明某项架构升级究竟改善了哪种行为；每个指标给出分母、金标准和置信不确定性。

**现有基础：** 现有 `ROUND_REVIEW` 可区分核心/支持性工作，v3.4 索引能记录主张审查，v4.0 R16—R17 具备题目与离线回放轨迹。

**进入条件：** R16—R17 有经过审核、可重放且独立隔离的任务结果。

## 2. 设计裁决与数据流

### 18.1 指标按真值来源分层

- **确定性：**预算违规数、重放失败数、非法写入成功数、重复事件、原文 SHA 误引、误提升主张状态。
- **基准真值：**隐藏反例命中率、已知覆盖识别率、非事实声称率、错误归责率。
- **专家审查：**复杂安全归约缺口、创新性判断、是否推进核心目标；需双盲或至少独立复核。

### 18.2 统计注意

必须明确成功样本数、总样本数和 95% 区间；样本只有几题时，报告原始计数和个案，不以大幅百分比声称一般化能力。对比 A/B/C/D 时固定同一题目集和工具预算，按任务配对报告差异，不能把不同任务类型的得分直接平均成“科学能力”。

## 4. Codex 必须完成的实现步骤

1. 为每项指标定义 numerator、denominator、排除条件、数据源与解释范围。
2. 实现对同一题的配对比较（baseline vs enhanced），保存各题结果和版本。
3. 对跨任务模型差异，列出固定模型、推理强度、单题 token 与调用次数（若 CLI 无法获得 token，标为 UNKNOWN，不猜测）。
4. 报告算法支持置信区间，但不能把区间显示精度当成真实性能精度。
5. 加入漏检计数：没有证据支持的监督成功不得记作科学成功。
6. 生成自动报告后仍保留人工审查格；人工标注可核查人员和证据版本。

## 5. 输入、输出与接口约定

对于二项样本结果，报告应使用独立块公式，例如：

\[
\begin{aligned}
s &= \text{通过金标准的题目数},\\
n &= \text{进入统计的有效题目总数},\\
\widehat{p} &= \frac{s}{n},\qquad n>0
\end{aligned}
\]

实际 Python 指标接口应使用英文变量命名与明确定义，不依赖截图识别；数学公式在正式论文输出中再使用严格符号系统。


## 6. 必做的离线自动测试

- 分母为 0 时输出 `UNDEFINED`，而非 0% 或 100%。
- 两个版本同一真实 case 必须按 ID 配对；多次重放不能作为独立题目数量。
- 缺少 oracle 时结果不能进入精确命中率。
- 一个被模型错误认可的候选定理计入错误认可指标，不按文本质量加分。
- 基准题改变时，旧版本报告继续指向旧 oracle SHA。

## 7. 本轮验收标准

- 输出 A/B/C/D 的逐题差异、汇总、成本与不确定性，而非只给一项综合总分。
- 样本过少时保留“结论不足”的明确标识。
- 实验报告能反向追溯原始回放轨迹与金标准。

## 8. 停止、回滚及禁止事项

任何评价模型只能辅助标注，无法独立建立公开数学定理的新颖性与正确性金标准。
