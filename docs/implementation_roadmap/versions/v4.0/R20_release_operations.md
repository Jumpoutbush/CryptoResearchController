# v4.0 · 开发轮次 R20：运行可观测性、版本发布和灾难恢复演练

> **执行状态：待开发（计划文件）**。本文是交给 Codex 的实施规格，并非已完成的功能说明。
> **基准：** `Jumpoutbush/CryptoResearchController@67618536ecd172b2fad24843daf291489e226c2e`；执行前以本机较新、已提交的源代码为准。
> **轮次类型：** 软件开发轮次；不得消耗任何个人科研项目的研究预算。

## 1. 本轮唯一目标

打通跨项目的只读状态总览、异常告警、成本追踪与一键禁用；用真实离线回归和 Windows 本地验证决定 v4.0 是否可发布。

**现有基础：** 现有 `research.cmd status`、日志目录、路线账本、监督事件、知识图谱、候选状态和基准报告已经可以聚合展示。

**进入条件：** R16—R19 完成，所有旧版回归测试已经可重复执行。

## 2. 设计裁决与数据流

### 20.1 运行概况

建议输出一个本地只读总览：每个项目的 phase/decision、冻结目标 SHA、路线已用预算、活动尝试、上次有效科研结果、监督待办、证据图失效数、候选摘要及最新基准版本。可先只实现 `research.cmd dashboard --json`，可选静态 HTML 后续再加，无需常驻网页服务。

### 20.2 发布定义

要求 v3.3—v4.0 的所有关键不变量回归通过；单一具体加密项目中的科学结论只有原 G0—G8 审查能够认可。运行 30 个基准任务不是发布的充分条件；还要有稳定性、恢复、权限及退出路径。

### 20.3 失败恢复

包括模型不可用、Codex CLI 断线、监督输出无效、知识索引损坏、候选记录修订冲突、评价器金标准受污染、Windows 编码和文件锁冲突。停用每个新功能不应破坏旧研究状态。

## 3. 修改范围（新增文件均为规划路径）

- 新建 `operations/dashboard.py`、`operations/health.py`、`operations/release_check.py`（规划路径）。
- 增加 `docs/RELEASE_V4_0.md`、`docs/MIGRATION_V3_2_TO_V4_0.md`。
- 新建 `tests/test_v4_release_gates.py`、`tests/test_disaster_recovery.py`。
- 统一 CLI 只读 `dashboard --json`、`health --offline`（实现后发布）。

## 4. Codex 必须完成的实现步骤

1. 实现跨项目读取时只输出必要元数据，不复制私有论文全文或密钥。
2. 检查路由/监督/候选/图谱/evaluation 各自版本号、损坏记录和可恢复状态。
3. 实施模拟断电演练，确认已接受科研轮次和已审查定理等级不丢失。
4. 设计滚动升级：功能默认关闭→单模拟项目→一个用户自愿启用的项目→其他项目；每步保留回滚点。
5. 实施专门的 Windows `cmd`/PowerShell UTF-8、Git 忽略目录、Codex 登录和模型可用性测试；无法调用真实模型时清楚标记未测试。
6. 生成最终 release gate 报告，包括逐项测试、原始证据、人工批准与限制。

## 5. 输入、输出与接口约定

总览输出建议：

```json
{
  "controller_version": "v4.0-development",
  "project_count": 3,
  "projects": [{"id": "...", "phase": "...", "route_used": 0, "supervision_pending": 0, "invalid_claims": 0}],
  "overall_health": "REQUIRES_OPERATOR_REVIEW"
}
```

上述值只是模式示意；真实项目数与健康状态必须由本机运行时计算。


## 6. 必做的离线自动测试

- 关键 T01—T15 全部通过；旧命令无行为回归。
- 将 `state/knowledge` 删除可安全重建，不能影响原始主张记录。
- 模拟监督日志损坏或指南冲突，仍能禁用监督并继续旧路线。
- 某个科研项目报告 `NEEDS_REVIEW` 时，dashboard 不能显示研究“正常完成”。
- 离线/模拟/真实模型测试分别统计，禁止混为一个通过标记。
- 所有新功能可逐项关闭并保留历史证据。

## 7. 本轮验收标准

- 生成一份完整 `RELEASE_V4_0.md`，每项发布门禁都附真实测试来源、责任人和回滚办法。
- 独立监督、知识图谱、候选搜索和评价功能分别完成隔离测试，综合恢复演练通过。
- 发布状态须由用户依据测试正式批准；工具自身不能自宣 v4.0 全部科学能力通过。

## 8. 停止、回滚及禁止事项

用户未明确授权，禁止执行真实付费科研试验、全量自动修改个人项目或推送 GitHub。

- 填写修改文件列表、设计偏差及理由、`git diff --stat`。
