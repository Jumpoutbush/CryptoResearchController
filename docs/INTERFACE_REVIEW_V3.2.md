# v3.2 新增接口审查记录

本次检查覆盖初始化、固定问题、有限研究尝试、独立核查、主张依赖、理论批准和旧版升级。现有个人项目没有写入新初始化文件；只有用户新建项目或明确调用 initialize 才启用该流程。

| 检查点 | 修订后的行为 |
| --- | --- |
| 原始 idea 如何进入初始化 | new --idea-file 保留原文和版本，首轮动态加载 initialize_from_idea.md |
| 模板是否仅为静态附件 | prompt --initialize 能看到最终注入内容；初始化输出有清单和摘要检查 |
| 缺信息是否冒充已完善 | 阻塞问题进入 NEEDS_INPUT 并暂停；不能登记含占位符的精确问题 |
| 初始化是否覆盖个人输入 | 模型只能生成派生文档；原始输入与 idea 受保护，自定义检索参数保留 |
| 初始化之后是否重复 INTAKE | attempt start 自动转入 PROOF，保留路线与已选 idea |
| 跨轮是否更换问题 | 绑定命题版本、输入、假设和目标；变更后要求显式关闭并审核 |
| 失败是否可免费无限重试 | 调用预约在项目事务之外记账；失败轮回滚仍保留费用计数 |
| 文本重写是否算进展 | 新文字仅记候选产物；新的独立审查结果或准确机器见证才重置数学停滞 |
| 模型是否可以自批主张 | 主张图、审批与问题池受保护；新提案只能导入候选状态 |
| Lean 退出码是否能直接放行 | 工具通过后仍待声明、依赖、公理范围与新颖性审核 |
| 旧上游被修正后是否自动放行下游 | 下游绑定旧版本，保持待重新验证，必须显式重新绑定并审查 |
| 系统代码是否在理论前自动启动 | 系统阶段前置阻止；理论批准绑定具体主张与完整关键义务闭包 |
| 原有路线预算是否失效 | 两套预算同时限制；需路线复评时先暂停尝试，不自动换主线 |
| 新增无关 idea 是否中断正在证明的问题 | 未固定的新想法可加入池；只有改变已固定输入才使当前尝试过期 |

验证结果：102项离线单元与集成测试通过；4个准确整数样例通过；在含空格目录中将 Unified-v3 升级至本版，两项目本地检查和 dry-run 通过。459份既有个人项目、参数、状态与 Git 文件逐字节保留，自定义 max_seconds=1337 保留，重复更新无额外写入。新项目根目录/子目录的初始化预览接口均通过。

验证范围：真实子进程链使用模拟 Codex，Lean 调用使用模拟工具测试状态边界；未执行真实付费模型请求或真实 Lean 数学证明，未做原生 Windows 终端测试。当前可自动运行准确整数谓词搜索与本地 Lean 适配；任意密码协议安全性、形式声明对应和定理级新颖性仍需要具体证据与独立技术审核。没有自动 Comparator 集成，也没有大规模问题搜索或并行智能体调度。

更新包只包含框架、模板、测试和手册。升级器保留原始 .git；Git 忽略规则不会自动移除旧索引里已经跟踪的个人文件，需用户按现有仓库策略管理。
